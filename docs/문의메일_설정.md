# 편지 문의 폼 설정

현재는 **입력창과 서버 발송 코드가 준비된 상태**입니다. 계정·환경변수를 설정하지 않으면 ‘메시지 전송 준비 중’으로 표시되며 발송되지 않습니다. 화면이나 배포용 정적 파일에는 받는 사람의 주소가 포함되지 않습니다.

## 1. Resend 준비

1. [Resend](https://resend.com/)에 가입합니다.
2. Domains에서 발송에 사용할 **본인이 관리하는 도메인**을 추가하고 DNS 인증을 완료합니다. 웹사이트 자체는 Vercel 주소를 사용해도 됩니다.
3. 인증한 도메인의 발신 주소를 정합니다. 방문자 이메일을 발신 주소로 사용하지 않습니다.
4. 해당 도메인에 대한 Sending access API 키를 만듭니다. 키를 채팅, Figma, 소스 파일에 붙여 넣지 마세요.

도메인이 아직 없다면 먼저 가입과 폼 검토까지 진행하고 발송 활성화는 보류할 수 있습니다. Resend의 테스트 발신 주소는 테스트 제약이 있으므로 공개 서비스용 설정과 구분해야 합니다. [공식 도메인 인증 안내](https://resend.com/docs/dashboard/domains/introduction)

## 2. 자동 전송 확인 준비

[Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/get-started/)에서 Managed 위젯을 만들고 실제 배포 사이트의 호스트 이름을 등록합니다. 로컬에서도 확인하려면 `localhost`와 `127.0.0.1`을 위젯에 등록합니다. Site key와 Secret key를 발급받습니다. 실제 사이트에 테스트용 키를 사용하지 않습니다.

## 3. Vercel 비공개 설정

프로젝트의 Settings → Environment Variables에 다음 값을 등록합니다. `.env.example`은 항목 안내이며 실제 값은 비워져 있습니다.

| 이름 | 넣을 값 | 노출 범위 |
| --- | --- | --- |
| RESEND_API_KEY | Resend 발송 키 | 서버만 |
| CONTACT_TO_EMAIL | 실제 받을 본인의 이메일 | 서버만 |
| CONTACT_FROM_EMAIL | Resend에서 인증한 도메인의 발신 주소 | 서버만 |
| CONTACT_SITE_URL | 사이트 주소의 origin, 예: `https://your-portfolio.vercel.app` | 서버 설정 |
| TURNSTILE_SITE_KEY | 위젯 Site key | 확인 위젯에 공개 |
| TURNSTILE_SECRET_KEY | 위젯 Secret key | 서버만 |

이 항목에 `VITE_`를 붙이지 않습니다. 발신/수신 주소는 이름이나 꺾쇠 없이 이메일 주소만 입력합니다. 사이트 주소는 프로토콜과 호스트 기준으로 검사하므로 미리보기와 운영 환경이 다르면 각각 올바른 값을 설정합니다. 값 변경 뒤 재배포해야 적용됩니다.

Vite 정적 배포만으로는 메일을 보낼 수 없습니다. 저장소 루트의 `api/contact.js`를 함께 Vercel Functions로 배포합니다. [Vercel Node.js 함수 안내](https://vercel.com/docs/functions/runtimes/node-js)

로컬 연결 확인은 `.env.example`을 `.env.local`로 복사해 실제 값을 넣고 개발 서버를 다시 시작합니다. 로컬의 `CONTACT_SITE_URL`은 브라우저에서 사용하는 주소, 예: `http://127.0.0.1:5173`입니다. `.env.local`은 Git에서 제외됩니다. `npm run preview`는 정적 미리보기이므로 문의 API는 `npm run dev` 또는 Vercel에서 확인합니다.

## 4. 실제 발송 확인

계정과 배포 설정을 마친 후 본인이 테스트 편지 한 통을 보내 실제 수신함과 스팸함을 확인합니다. 답장 버튼이 방문자의 주소를 가리키는지도 확인합니다. 성공 안내는 Resend가 발송 요청을 접수한 경우에만 뜨며, 수신함 도착을 보장하는 안내는 아닙니다.

입력 정보는 문의 응대에 사용하며 별도 사이트 DB에는 저장하지 않습니다. Resend 발송 기록과 본인 메일함에는 문의가 남을 수 있습니다. 실제 공개 운영에 맞춰 정보 보관·삭제 기준과 안내 문구를 정한 뒤 공개하세요.

## 구현 및 검증

- 방문자의 이름·이메일·내용만 입력하고 수신자는 서버 설정으로 고정합니다.
- 전송 동의, 입력 길이, Origin, 숨김 필드와 Turnstile 토큰을 서버에서 확인합니다. 외부 오류나 비밀 설정은 응답에 노출하지 않습니다.
- 실패하면 입력을 유지합니다. 같은 내용을 다시 시도하면 Resend의 동일한 Idempotency-Key를 사용합니다. [Resend 발송 API](https://resend.com/docs/api-reference/emails/send-email)
- Turnstile 확인에 실패하면 발송하지 않습니다. [서버 검증 안내](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)
- `npm run test:contact`는 외부 발송을 하지 않는 모의 테스트입니다. 실제 계정 연결과 수신 확인은 아직 하지 않았습니다.
- 이전 제작 과정은 `docs/asset-history/v52-before-private-contact`에 보존했습니다. 이 경로는 공개 정적 파일인 `public`·`dist`에 포함되지 않습니다. 원본 이력서·문서를 별도로 업로드할 때는 연락처가 들어 있는지 다시 확인해야 합니다.
