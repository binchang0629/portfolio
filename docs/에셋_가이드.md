# 에셋 가이드 · V31

작업 폴더: C:/bin/portfolio. 파스텔 책상과 흰 플레이어의 방향을 기준으로 독립 탑뷰 카세트 원본을 만들었습니다. 다섯 카세트는 공통 원본을 공유하고 책상 위 회전, 색, 감긴 양만 다릅니다.

## 활성 파일

public/assets/

활성 재질은 PNG 7개와 SVG 스티커 5개입니다. PNG는 카세트·플레이어·책상 1536×1024, 보관함 1440×1092, 플라스틱 표면 샘플 원본 1254×1254입니다. 원본 주변에 배경이나 알파 가장자리 잡음이 남아 있어 외곽 SVG 마스크로 사물 영역만 표시합니다. 실제 WebGL 3D 모델이나 순수 벡터 에셋은 아닙니다.

## 공통 카세트와 릴

CassetteSurface.jsx가 책상과 플레이어 안에서 같은 카세트를 조립합니다. clean-v1.png는 빈 내부와 외피, 원본 render-v1.png는 검정 코일 표면을 제공합니다. 허브는 TopViewHub.jsx의 얕은 원형 벡터 구조입니다. 종이 위 문구와 스티커는 실제 SVG 텍스트·벡터입니다.

- topview-geometry.js에서 외곽, 종이, 내부 창, 두 허브의 좌표를 관리합니다.
- 좌우 허브 중심은 (469,441), (1068,441)이며 바깥 반지름은 109입니다. 두 릴 모두 동심원과 6개 안쪽 톱니를 공유합니다.
- 코일 표면을 샘플링할 때 원본 허브와 그 아래 회색 초승달 테두리는 반지름 128 마스크로 먼저 제외합니다. 감긴 양에 따라 허브가 확대되어 중복 테두리로 나타나지 않습니다.
- 두 코일은 같은 중심의 검정 동심원과 사진 표면을 조합하고, 중간 공간을 가로지르는 리본은 그리지 않습니다.
- 플레이어 안에서는 균일 배율 392/599와 평행 이동만 적용합니다. 가로·세로 비율을 달리하거나 릴을 찌그러뜨리지 않습니다.
- 1440px 검수 화면에서 삽입·책상 카세트의 배율 비는 0.99629, 두 릴 축의 위치 오차는 0.001px 미만입니다.
- 삽입 상태는 기존 플레이어 문틀로 가려집니다. 본체와 실제 기계식 버튼의 재질은 그대로 유지합니다.

회전·감김은 src/lib/tape-mechanism.js 및 useTapeTransport.js에서 제어합니다. 사진 기반 외피의 반사는 물리적으로 다시 계산하지 않습니다. 릴은 회전 형상 마스크와 고정 조명 레이어를 분리해 중심·윤곽·빛 방향을 유지합니다.

## 독립 보관함

ArchiveTray.jsx에는 floor, stored-tapes, inner-shadow, rim, dividers 레이어가 있습니다. 같은 사진을 SVG 영역별로 표시하고 안쪽 그림자는 별도 벡터로 추가합니다. 바깥 접지 그림자는 책상 좌표의 CSS에서 처리하며 회전하는 사물의 내부로 넣지 않습니다.

5칸 함은 책상 위 테이프 한 개와 비슷한 가로 크기, 약 0.8배의 세로 크기입니다. 넓은 앞면 패널 대신 윗테두리에 MORE TAPES 라벨을 놓았습니다. 보관함에 실제 추가 작업이 생기면 세워 꽂힌 테이프는 얇은 등 부분으로 표시합니다. 현재 archiveTracks는 비어 있으므로 가짜 작업이나 중복 카테고리 테이프는 표시하지 않습니다.

보관함에서 꺼낸 추가 작업을 삽입하면 책상에서 사라집니다. 꺼내거나 다른 작업으로 교체하면 보관함으로 돌아옵니다. 반환 순간을 입체적으로 감추는 별도 이동 애니메이션은 아직 추가하지 않았습니다.

## 책상과 문구

desk-topview-v1.png는 책상·노트·메모·펜을 포함하는 정적 배경입니다. 이전 큰 보관함은 배경에서 제거하고 독립 사물로 옮겼습니다. 노트·메모·펜 전체가 개별 투명 PNG나 벡터로 분리된 것은 아닙니다. 글자와 클릭 영역은 React입니다. 다섯 테이프의 위치·회전·색·감긴 양은 src/data/portfolio.js에서 수정합니다.

## 확인과 과정 보존

`npm run lint`, `npm run build`, `npm run check:assets`로 코드와 파일을 확인합니다. 실제 동작·모바일·축 및 배율 검수는 docs/design-v29/refinement-v29-qa.json에 있습니다. 생성 방식은 내장 image_gen이며 생성 프롬프트와 파일 경로는 docs/design-v29/imagegen-topview-v29.json에 기록했습니다.

이전 카세트 재질·큰 보관함 배경과 구현은 docs/asset-history/v27-before-shared-camera, v28-before-topview-assets, v29-retired-assets에 보존합니다. V27~V28의 코드와 검수 자료를 현재 에셋과 혼동하지 않도록 구분합니다.


## V31 릴 회전 수정

이전 방식은 입체 허브 사진 전체를 돌려 안쪽 벽과 반사까지 회전했습니다. TopViewHub는 얕은 동심원 링을 만들고 안쪽 톱니의 마스크 형상만 회전합니다. 플라스틱 표면과 바깥 성형 링, 조명은 고정된 좌표를 공유합니다. SVG의 얕은 모서리 조명을 사용하며 실제 3D 모델은 아닙니다.

polymer-sample-v1.png는 내장 이미지 생성 결과에서 플라스틱의 평평한 표면 패치만 가져오는 재질 원본입니다. 생성 결과의 허브 모양·기울기·그림자는 사용하지 않습니다. 패치 좌표는 (520,150), 크기는 90×60이며 원본 전체를 회전시키거나 하얀 허브 사진을 붙이지 않습니다.

재생·정지·되감기·빨리 감기, 축 고정·원형 유지·고정 조명·각 릴의 서로 다른 속도, 모바일·모션 줄이기를 docs/design-v31/reel-motion-v31-qa.json에서 확인합니다. 제작 프롬프트와 실제 사용 범위는 reel-material-v31.json에 있습니다. 변경 전 코드는 docs/asset-history/v30-before-topview-hubs에 보존합니다.

- 다섯 테이프의 삽입·재생·정지·꺼내기, 원형 릴의 균일 배율, 빈 축과 삽입 축의 일치, 브라우저 오류 없음 및 lint/build/check:assets 확인.

## V33 · 밖과 안의 카세트 크기 통일 (2026-09-28)

- 밖의 카세트를 고정 20%/모바일 310px로 표시하던 대신, 플레이어 폭과 삽입 배율에서 계산한 크기를 사용한다.
- 계산: 카세트 viewBox 폭 × 삽입 배율 ÷ 플레이어 viewBox 폭. 플레이어 폭의 약 69.43%가 밖의 카세트 SVG 폭이다.
- PC에서는 원래 크기가 거의 맞아 미세한 조정만 필요했다. 모바일에서는 독립된 310px 제한 때문에 더 컸으므로 플레이어에 맞게 줄어든다.
- 문에 가려진 삽입 테이프의 높이/폭에 전체 테이프를 억지로 맞추지 않는다. 공통 에셋의 전체 배율과 원형 릴 크기, 두 축 사이 거리를 유지한다.
- 1920×1080, 1366×768, 1440×600, 모바일 390×844에서 다섯 테이프의 삽입 전후와 꺼내기 크기를 확인했다. 같은 페이지를 1024px 폭으로 바꿔도 배율이 맞는다.
- 예시 릴 간격: 밖 132.058px, 안 132.063px. SVG 배치의 소수점 반올림 범위다.
- lint/build 통과. PC 100vh 및 모바일 가로 넘침 없음 확인. 이전 코드는 `docs/asset-history/v32-before-shared-cassette-size`에 보존했다.
- 측정 및 화면: `docs/design-v33/cassette-size-qa.json`, `portfolio-size-matched.png`, `portfolio-size-matched-mobile.png`.


## V34 · 하단 자기 테이프 경로 (2026-09-28)

- 릴에 감긴 부분만 있던 공통 카세트에 독립 SVG `TapeRibbon` 부품을 추가했다. 양쪽 릴 외곽에서 하단 가이드로 내려가고, 아래 헤드 개구부 쪽을 수평으로 지나 반대쪽 릴로 이어진다. 가운데 창을 가로지르는 띠는 만들지 않는다.
- 하단 경로는 소스 좌표 y=864이며 가이드 중심은 (214, 830), (1324, 830), 반지름 34다. 아래 캡스턴 구멍을 가로지르지 않도록 경로를 하단 가장자리로 배치했다.
- 두 릴의 반지름과 가이드 원의 공통 외접선을 계산한다. 감긴 양이 달라져도 릴 외곽과 연결된 상태가 유지된다. 띠는 라벨 뒤로 가려지고 플레이어 안에서는 문 뒤로 일부 가려진다.
- 그림 파일에 선을 구워 넣지 않았다. `src/components/TapeRibbon.jsx`, `src/lib/tape-path.js`에서 독립 편집할 수 있다. 밖의 다섯 테이프와 삽입 상태가 같은 부품을 사용한다.
- 101개 감긴 양에서 원에 닿는 지점과 접선 방향을 검사했다. 브라우저에서 다섯 테이프, 삽입, 재생·되감기에 따른 경로 변화, 정지 시 고정, 꺼내기 복원을 확인했다.
- 기존 버전은 `docs/asset-history/v33-before-tape-path`에 보존했다. 확대 화면과 확인 기록은 `docs/design-v34`에 있다.


## V35 · 내부 릴·띠와 투명 케이스의 깊이 (2026-09-28)

- 기존에는 바탕 케이스 사진 위에 검정 띠와 릴을 그대로 그려 표면 위에 붙은 느낌이 났다. 공통 카세트의 쌓임을 뒷면 → 내부 릴·가이드·띠 → 투명 케이스 표면 → 앞쪽 몰딩과 개구부 테두리 → 라벨·글자로 정리했다.
- `CassetteCover.jsx`는 원래 clean 케이스 사진의 표면 반사를 18%로 겹친다. 새로 렌더한 이미지나 평면 색칠로 원본을 대체하지 않는다. 중심 축 구멍은 마스크로 열어 두고, 창 테두리와 하단 플라스틱·구멍의 앞부분은 원래 사진으로 가린다.
- 아래 띠 경로와 접선 계산, 안팎의 카세트 배율은 유지한다. 케이스 표면은 카세트 좌표에 고정되어 릴과 함께 회전하지 않는다.
- 이전 코드는 `docs/asset-history/v34-before-cassette-depth`에 보존했다. 확대 비교 화면과 확인 기록은 `docs/design-v35`에 있다.
- 다섯 테이프의 겹침 순서, 101개 감긴 양의 접선 연결, 삽입·재생·되감기·정지·꺼내기 확인.


## V36 · 릴 옆 접점과 띠의 이동 효과 (2026-09-28)

- SVG 선의 두께가 접선 밖으로 반씩 나와 릴 옆 끝이 돌출되어 보이던 부분을 수정했다. 실제 띠 바깥 가장자리가 감긴 원의 외곽과 맞도록 중심선을 반 두께 안으로 넣고, 잘린 끝은 릴 아래에 숨긴다. 101개 감긴 양에서 가장자리 정렬을 확인했다.
- 띠의 옅은 표면 결을 경로 방향으로 이동한다. 별도 애니메이션 타이머 없이 릴·감긴 양과 같은 `useTapeTransport` 상태의 누적 이동량 `travel`을 사용한다.
- 재생: 왼쪽에서 오른쪽 릴로 이동. 되감기: 반대 방향. 빨리 감기: 3배 이동. 정지: 띠와 릴 모두 고정. 가이드와 케이스 반사는 회전하거나 이동하지 않는다. 동작 감소 설정에서는 결 이동을 추가하지 않는다.
- 같은 시각의 애니메이션 프레임을 받았을 때 테이프 끝으로 판단해 정지하지 않도록 시간 간격이 없는 프레임을 건너뛴다. 브라우저에서 해당 조건을 주입해 재생 유지까지 확인했다.
- PC·모바일의 재생, 정지, 되감기, 빨리 감기, 꺼내기 및 기존 레이어 고정 확인. 화면과 확인 기록은 `docs/design-v36`에 있다.
- 이전 파일은 `docs/asset-history/v35-before-smooth-tape-contacts`에 보존했다. 띠·케이스·릴은 계속 독립 부품으로 편집 가능하다.


## V39 · 7칸 보관함과 현재 다섯 테이프 보관 (2026-09-28)

- 원래 투명 아크릴 사진의 바닥·칸막이·테두리 질감을 SVG에서 재조립해 7칸, 칸막이 6개로 만들었다. 기존 5칸의 위아래 칸막이 흔적을 제거하고 새 위치에 맞췄다. 새 AI 렌더 또는 통짜 이미지로 교체하지 않았다.
- 용량과 칸 위치는 `src/assets/archive/tray-geometry.js`에서 공유한다. 보관된 테이프는 공통 카세트 이미지의 윗면 부분을 세워 꽂힌 얇은 면으로 렌더하고, 기존 번호·색·제목을 유지한다.
- 현재 다섯 테이프는 처음에는 책상에 있다. 플레이어 또는 보관함에 끌어 넣을 수 있다. 보관함이 회전되어 있어도 SVG 좌표로 실제 칸을 찾아 보관한다. 차 있는 칸에 놓으면 첫 빈 칸을 사용하고 기존 테이프를 덮어쓰지 않는다.
- 각 테이프는 책상/플레이어/보관함 중 한 곳에만 존재한다. 상자에 넣으면 책상에서 사라지고, 저장된 칸을 누르면 책상으로 꺼낸다. 플레이어에 넣은 뒤 꺼내 다시 상자에 보관할 수 있다. 빈 두 칸에 새 콘텐츠를 임의로 만들지 않는다.
- 상자 아래의 이름을 눌러 보관함 목록을 연다. 모바일에서는 목록의 보관 버튼으로 다섯 테이프를 넣는다. 메뉴 내용은 보관 상태에 따라 즉시 갱신한다. 플레이어 안의 테이프도 메뉴에서 보관할 수 있으며 재생은 멈춘다.
- 배치 초기화는 현재 다섯 테이프를 책상의 기본 위치로 돌린다. 추가 프로젝트가 archiveTracks에 등록되면 초기 보관함에서 시작한다. 현재 archiveTracks는 비어 있으며 새 프로젝트를 임의로 추가하지 않았다. 보관 상태는 현재 실행 중인 화면에 적용된다.
- PC 실제 드래그로 다섯 테이프를 1·3·4·5·7번 칸에 넣고 두 빈 칸 유지, 중복 없음, 직접 꺼내기, 재생, 꺼내서 재보관, 초기화, 차 있는 칸 처리와 모바일 보관·재생을 확인했다. 화면과 확인 기록은 `docs/design-v39`에 있다.
- 이전 파일은 `docs/asset-history/v38-before-seven-slot-storage`에 보존했다.
