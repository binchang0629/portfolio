# 케이스 스터디 작성 규칙

프로젝트 상세 페이지(테이프를 재생하면 열리는 설명 페이지)를 만들고 고칠 때 지키는 규칙입니다.
작업하면서 받은 피드백을 모아 정리했습니다. 새 규칙이 생기면 여기에 추가합니다.

## 1. 구조: 내용과 레이아웃을 나눈다

- 내용은 `src/data/cases/<프로젝트>.js`에만 씁니다. 레이아웃은 `src/components/CaseSection.jsx`가 그립니다.
- 새 프로젝트는 `src/data/cases/_template.js`를 복사해 채우고, `src/data/projects.js`에서 `{ id: '...', ...케이스 }`로 펼쳐 넣습니다.
- 이미지는 `public/cases/<id>/`에 WebP로 두고, 데이터에 원본 크기 `w`, `h`를 적습니다(레이아웃 흔들림 방지).
- 레이아웃 종류: `lead`(대표 이미지), `cards`(근거·요점), `match`(문제 → 판단), `annotated`(화면 주석), `compare`(과정·비교), `links`(자료).
- 섹션은 `side: 'A' | 'B'`로 카세트 두 면에 나눕니다. 면 이름은 `sides`에 적습니다. 예: A 기획 / B Pairing 페이지.
  - A면: 팀이 함께 조사하고 방향을 정한 과정
  - B면: 내가 맡은 페이지와 기능 설명, 결과, 회고

## 2. 내용: 지어내지 않는다

- 조사 수치, 인터뷰, 테스트 결과는 실제로 한 것만 씁니다. 출처(`source`)를 적습니다.
- 아직 모르는 내용은 `[실제 결과 입력]`처럼 대괄호로 적습니다. 화면에 점선 칸으로 보입니다.
- 설계 의도와 확인된 결과를 섞지 않습니다. `status: 'intent' | 'verified' | 'unverified'`로 구분합니다.
- 해당 과정이 없던 프로젝트는 섹션을 지우지 말고 `hidden: true`로 숨깁니다. AI 활용 섹션도 AI를 쓴 프로젝트에서만 켭니다.
- 다른 사람의 포트폴리오 내용은 가져오지 않습니다. 레퍼런스는 배치와 흐름만 참고합니다.
- 팀 작업과 내 작업을 구분해서 씁니다.
- 원본 자료에 있던 아이디·비밀번호·연락처는 옮기지 않습니다.

## 3. 문구: 짧게, 결론으로

- 제목(`title`)은 항목 이름이 아니라 알게 된 결론으로 씁니다. 짧게 두 줄 이내로 쓰고, 줄은 `\n`으로 직접 나눕니다.
  - 나쁜 예: "사용자 조사"
  - 좋은 예: "맛으로 고르는데,\n맛을 설명하는 말이 없다"
- 모든 제목을 "~했습니다" 같은 긴 문장으로 똑같이 쓰지 않습니다(AI가 쓴 느낌이 납니다).
- 제목 위에는 짧은 영문 머리말(`kicker`)을 둡니다. 예: Problem, Research, Feature 01
- 본문(`body`)은 두세 문장만 씁니다. 설명은 이미지가 하게 합니다.

## 4. 줄바꿈: 문장 중간에서 잘리지 않게, 들쭉날쭉하지 않게

`src/components/Sentences.jsx`가 실제 칸 너비를 재서 아래 규칙대로 줄을 나눕니다. 본문, 요약, 표 칸에 모두 적용됩니다.

1. 문장이 끝나면 다음 줄로 넘깁니다. 문장이 칸 끝에 걸려 중간에서 잘리면 AI가 만든 느낌이 납니다.
2. 한 줄에 다 들어가는 문장은 쉼표가 있어도 나누지 않습니다.
3. 한 줄을 넘치는 문장만 쉼표에서 내립니다.
4. "HTML, CSS, JavaScript" 같은 나열의 쉼표에서는 끊지 않습니다.
5. 짧은 문장끼리는 한 줄로 합칠 수 있습니다. 무조건 내리지 않습니다.
6. 줄 길이가 비슷해지도록 고르고, 한두 단어만 떨어진 줄은 만들지 않습니다.
7. " · " 구분점이 줄 맨 앞에 오지 않게 합니다.
8. 쉼표가 없는데 넘치는 문장은 두 줄 길이가 비슷하게 나눕니다. 원하는 곳에서 끊으려면 본문에 `\n`을 넣습니다.
9. 데스크톱(1440, 1280)에서 한 번 확인하고, 두 줄로 넘어가는 문장이 너무 길면 문장을 둘로 나누는 쪽으로 고칩니다.

## 5. 디자인: 이미지 중심의 색 띠 페이지

레퍼런스는 이미지 중심의 긴 포트폴리오 페이지입니다(색 띠가 번갈아 이어지고, 짧은 가운데 정렬 제목 아래 큰 화면이 놓이는 구성).

- 섹션마다 화면 폭 전체를 채우는 띠를 깝니다. `tone: 'light' | 'dark' | 'brand'`를 번갈아 써서 리듬을 만듭니다.
- 띠 색은 그 프로젝트의 스타일 가이드 색을 `theme`에 넣어 씁니다. 예: 국순당은 주황 `#F29556`, 먹색, 밝은 배경.
- 제목과 설명은 가운데 정렬하고, 화면 캡처는 띠 폭 가까이 크게 보여줍니다.
- 다음은 AI 같아 보여서 쓰지 않습니다.
  - 테두리 박스 카드, 큰 숫자 카드 세 개가 나란히 놓인 대시보드식 줄
  - 점선 알약 태그
  - 모노 폰트 라벨 남발
  - 좁은 칸에 글이 대부분이고 이미지는 작게 들어간 구성
- 요점은 박스 대신 얇은 선으로 나눈 가로 줄로 보여줍니다.
- 케이스 페이지에서는 오른쪽 트랙 목록을 쓰지 않습니다. 현재 위치는 상단 NOW PLAYING 바가 보여줍니다.

## 6. 이미지와 차트

- 슬라이드나 화면을 잘라 쓸 때는 어두운 배경 모서리가 딸려 오지 않게 자릅니다.
- 원본은 16:9여도 웹에서는 너비에 맞춰 반응형으로 보여줍니다.
- 그래프는 캡처하지 말고 숫자로 다시 그립니다(`chart`). 캡처한 그래프는 겹쳐 보이고 모서리가 지저분합니다.
- 비교할 이유가 없으면 막대는 항목당 하나만 둡니다. 여러 설문은 응답 수를 더해 하나로 합치고, 인원(예: 12명)을 옆에 적습니다.
- 강조할 항목만 브랜드색으로 칠합니다.
- 화면 주석 번호는 버튼이나 글자를 가리지 않게 옆에 둡니다.
