# 반려식물 관리 모바일 웹앱 · 개인 프로젝트

갱신일: 2026-09-28
상태: 작업 중
포트폴리오 분류: 03 DESIGN

## 프로젝트 소개

- 작업자: 정창빈
- 유형: 개인 모바일 웹앱 신규 기획·제작. 기존 앱 리디자인이 아닙니다.
- 한 줄 소개: 식물 상태를 확인하고, 비슷한 환경의 관리 경험을 비교해 행동과 결과를 기록하는 서비스.
- 대상: 관리 판단이 어려운 초보자, 경험을 기록·비교·공유하려는 경험자.
- 정식 이름: 미확정. Figma에 Planty 표기와 Leafit·repeat 이름 후보가 함께 존재.
- 현재 단계: Figma 기획·핵심 화면 설계 자료 확인. 전체 프로젝트는 작업 중이며 개발·배포 범위는 확인 필요.
- 작업 기간: 확인 필요.

## 문제와 목표

아래는 Figma의 문제 정의이며 모두 검증이 완료된 결과라는 뜻은 아닙니다.

- 정해진 물주기 일정이 실제 흙·잎 상태와 맞지 않을 수 있음.
- 많은 관리 정보에서 지금 필요한 정보를 찾기 어려움.
- 같은 식물이라도 계절·빛·실내 환경에 따라 관리 판단이 달라짐.
- 상태·관리 행동·이후 변화가 사진·기억·게시물로 흩어져 비교하기 어려움.
- 반복 기록의 부담과 기본 기능을 제한하는 구독 경험.

목표: 사용자가 실제 식물을 먼저 관찰하고, 유사 환경 사례를 참고해 관리 행동을 직접 선택하도록 돕습니다. 입력 부담을 줄이고 상태 → 행동 → 결과를 비교 가능한 기록으로 연결합니다.

## 기획 과정과 방향 변화

초기 메모에는 현실의 식물과 앱 속 식물을 함께 키우는 게임형 아이디어가 있습니다. 린캔버스와 현재 화면에서는 상태 확인과 실제 경험 비교가 핵심으로 구체화돼 있습니다. 게임형 아이디어는 현재 핵심 기능이 아닌 기획 변화로 기록합니다.

자료에는 데스크 리서치, 경쟁 앱 체험 기록, 초기 인터뷰 메모, 페르소나, 린캔버스가 있습니다.

핵심 검증 가설: 사용자는 하나의 관리 정답보다 유사 환경의 상태·행동·결과 사례를 유용하게 느낄 것입니다. 아직 가설이며 효과 검증 결과로 표현하지 않습니다.

## 주요 화면과 기능

다음은 ‘앱’ 페이지의 app 섹션에 존재하는 화면입니다. 화면 설계의 존재와 실제 기능 구현 완료를 구분합니다.

| 화면 | 사용자 경험 | 자료상 상태 |
| --- | --- | --- |
| Home | 오늘의 환경·확인할 식물·이어 기록할 결과 | 화면 설계 있음 |
| My Plants | 식물 목록·검색·상태 필터·추가 진입 | 화면 설계 있음 |
| Plant Detail | 현재 상태·최근 관리·관찰 기록 | 화면 설계 있음 |
| Care Check | 흙 상태 선택·관찰 안내 | 화면 설계 있음. 전체 단계 범위 확인 필요 |
| Similar Experience | 유사 환경의 행동 경향·개별 사례 | 화면 설계 있음 |
| Action | 사례를 참고한 행동 선택·기록 | 화면 설계 있음 |
| Result / My Log | 이후 상태 변화·메모 저장 | 화면 설계 있음 |
| Experience Data | 행동별 결과·환경별 경향 비교 | 화면 설계 있음 |
| Grow Point | 관찰·기록·공유 보상 | 기획과 확장 화면 자리 있음. 상세 완성 여부 확인 필요 |
| Grow Shop | 포인트를 식물 관리 혜택에 연결 | 기획과 확장 화면 자리 있음. 상세 완성 여부 확인 필요 |

핵심 흐름: 홈·내 식물 → 상태 확인 → 비슷한 경험 → 행동 선택 → 이후 결과 기록 → 경험 축적·비교.

## 설계 원칙과 보완할 점

- 실제 상태 확인과 지금 필요한 정보를 먼저 배치합니다.
- 상태·행동·결과를 짧은 선택과 메모로 기록합니다.
- GROW PASS는 기본 기능 제한보다 세부 분석·보상 확장을 제공하는 기획입니다.
- 린캔버스는 직접 판단을 강조하지만 일부 행동 화면은 추천처럼 읽힙니다. 참고 사례와 직접 선택의 관계를 명확히 해야 합니다.
- 복수 화면 버전이 있어 구현 전 기준 버전을 정해야 합니다.
- 결과 기록 시점, 사례·필터 결과 없음, 저장·네트워크 오류 화면은 추가 확인이 필요합니다.
- 사례 신뢰도·비교 기준·기록 부담은 검증할 과제입니다.
- 포인트·상점·구독의 기획과 실제 운영을 구분합니다.

**반려식물 관리 모바일 웹앱** · 개인 프로젝트 · 작업 중

식물의 현재 상태를 직접 확인하고, 비슷한 환경의 관리 경험을 비교해 다음 행동을 선택하는 모바일 웹앱을 설계하고 있습니다. 상태·행동·결과를 기록으로 연결해 자신과 다른 사용자의 경험을 참고하도록 구성했습니다.

상세 순서: 문제와 기획 근거 → 아이디어의 변화 → 핵심 흐름 → 직접 만든 화면 → 검증·보완 과제.

화면의 경험 건수·비율·유사도·환경 값은 예시 여부가 확인되지 않았으므로 실제 이용 데이터나 성과로 인용하지 않습니다. 시장 통계는 원문 검증 전 공개 소개의 근거 수치로 옮기지 않습니다.
