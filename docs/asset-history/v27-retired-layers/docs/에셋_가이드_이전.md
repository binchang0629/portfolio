# 에셋 가이드 · 2026.09.28

작업 폴더: C:/bin/portfolio. 실제 사용하는 파일은 public/assets, 마스크와 배치 좌표는 src/assets에 있습니다. 승인된 V2 재질과 현재 파스텔 책상 구도를 유지합니다.

| 요소 | 파일 | 수정 방법 |
| --- | --- | --- |

| 카세트 내부 창 | cassette/window.png | PNG 재질과 SVG 창 마스크 |
| 흰 릴 중심 | cassette/hubs.png | 좌우 중심 마스크로 분리한 PNG 재질 |
| 검정 테이프 코일 | Cassette.jsx + tape-mechanism.js | 중심이 같은 벡터 원. 감긴 양과 회전을 별도 제어 |
| 테이프 스티커 | cassette/stickers/*.svg | 독립 SVG. Figma 또는 벡터 편집기로 수정 가능 |
| 흰 플레이어 | player/material.png | 원본 PNG에서 SVG 마스크로 분리. 오른쪽 버튼은 실제 버튼 |
| 마스크·릴 중심·비례 | src/assets/*/geometry.* | SVG 좌표 수정. 삽입된 테이프도 동일 좌표 사용 |

현재 사용하는 8개 PNG는 원래의 1536×1024 좌표계를 유지하는 **재질 원본**입니다. 원본 파일을 단독으로 열면 현재 사물 외의 부분도 보일 수 있으며, 사이트에서는 마스크 안쪽만 표시됩니다. 투명 배경 완성 PNG나 모든 사물이 분리된 순수 벡터 묶음은 아닙니다. 노트·메모·보관함·펜의 정적 재질은 아직 하나의 책상 배경에 포함돼 있습니다.

## 경로와 검수

앱은 src/assets/index.js의 경로 목록을 공유합니다. 파일 이름이나 위치를 바꿀 때 이 목록과 public/assets/manifest.json을 함께 갱신합니다. manifest의 SHA-256은 이번 정리 시점의 기록이며 교체를 막는 조건은 아닙니다.

`npm run check:assets`로 파일 누락·PNG 크기·SVG 영역을 확인합니다. `npm run lint`, `npm run build` 후 PC와 모바일에서 삽입·재생·꺼내기까지 확인합니다.

## 테이프와 보관함 확장

기존 다섯 카테고리는 src/data/portfolio.js의 tracks에서 수정합니다. 실제 추가 작업이 생기면 archiveTracks에 등록합니다. sticker는 about/team/design/branding/next 중 하나를 지정할 수 있고 생략하면 next 스티커를 사용합니다. 꺼낸 추가 테이프를 삽입하면 책상에서 사라지고, 꺼내거나 다른 테이프로 교체하면 보관함으로 돌아옵니다.

추가 이미지가 필요하면 public/assets/projects/<프로젝트명>/에 넣고 실제 작업 화면과 연결합니다. 현재는 프로젝트 대표 화면이 등록돼 있지 않습니다.

## 정면 삽입 에셋

책상 위 카세트는 Cassette.jsx의 비스듬한 사물 모습, 삽입된 카세트는 FrontCassette.jsx의 정면 부품을 조립한 다음 InsertedCassette.jsx에서 플레이어 시점에 맞게 투영합니다. 재생 중에는 비스듬한 사진을 회전시키지 않습니다. 삽입 테이프의 두 릴 중심은 같은 높이(y=465)이며, 정원 코일·동일 규격의 흰 허브·8개 치형을 각기 제어합니다. 좌우의 감긴 양은 같은 진행 상태를 공유합니다.

정면 PNG는 케이스와 종이 재질만 포함하며, 릴은 코드로 합성합니다. 생성 결과의 배경은 투명하지 않아 SVG 외피 마스크로 제거합니다. 케이스는 삽입 창에서 부분적으로 잘려 보입니다. 릴은 정면 좌표에서 회전하고, 케이스·라벨·코일·허브 전체에 같은 원근 변환을 적용합니다. 릴만 별도로 기울이거나 비스듬한 사진을 회전시키지 않습니다.

정면 릴은 케이스 정면 기준 좌우 488·1065, 높이 465에 배치했습니다. 삽입 시 이동량을 맞춰 플레이어 재질의 기존 스핀들 위치(690·818, 높이 478)에 정렬합니다. 창에서 아래쪽 가이드 부분은 가려집니다.


## V25 · 플레이어 시점에 맞춘 삽입

src/assets/player/cassette-plane.js에 삽입 평면과 창 가림 영역을 함께 기록했습니다. 플레이어 원본의 창은 사다리꼴이고 책상에 놓인 기기는 얕은 원근을 가지므로, 정면 에셋을 평평하게 덮는 대신 모든 부품에 동일한 3D 투영을 적용합니다. 두 허브는 플레이어의 기존 축에 계속 정렬됩니다. 화면 크기가 달라져도 같은 플레이어 좌표계로 비례를 유지합니다.

정면 부품 원본은 유지하며, 마스크·회전·감긴 양도 독립 편집 가능합니다. V24 화면과 이번 수정 전 코드는 docs/asset-history/v24-before-player-perspective에 보존합니다.

## V26 · 수납부 기준으로 크기와 원근 재조정

기존 이미지에 생성된 스핀들 좌표만 따라가던 V25 기준을 교체했습니다. 기존 두 축의 중앙이 실제 창 중앙보다 오른쪽으로 치우쳐 있었고, 수납부와 테이프의 윤곽도 별도로 조정되고 있었습니다.

카세트 외피의 네 모서리를 실제 수납부 [(591,400), (894,400), (895,570), (589,570)]에 일치시킵니다. 위·아래 폭 차이는 약 1%로 줄였으며 테이프 전체가 같은 변환을 따릅니다. 창은 수납부보다 작아 위·아래·옆 외피 일부를 가립니다. 허브 중심은 외피 중심을 기준으로 좌우 대칭인 (486,465)·(1051,465)에 둡니다.

PlayerWindowFrame.jsx로 원래 플레이어의 문틀을 삽입된 테이프 앞에 복원했습니다. 테이프 모서리와 나사가 문틀 위에 붙은 것처럼 보이는 것을 줄이고, 테이프가 문 안에 들어간 상태를 표현합니다. V25 소스는 docs/asset-history/v25-before-cassette-fit에 보존합니다.

## V27 · 한 렌더에서 플레이어·테이프·버튼 재질 통일

V24–V26의 개별 PNG + 평면 SVG 허브 + 별도 사각 버튼 조합은 현재 화면에서 사용하지 않습니다. 기존 코드는 과정으로 보존했습니다.

public/assets/player/coherent의 render-v1.png를 공통 기준으로 사용합니다. 플레이어, 기계식 버튼, 유리 문틀, 삽입된 테이프가 하나의 장면에서 같은 조명과 원근으로 표현됩니다. empty-interior-v1.png는 카세트를 뺀 내부, clean-interior-v1.png는 코일과 흰 허브만 제외한 같은 내부입니다. 본체와 버튼은 원본 렌더를 항상 공유하고 바뀌는 내부 영역만 마스크로 사용합니다.

IntegratedPlayer.jsx에서 원본 렌더의 실제 흰 허브를 좌우 각각 마스킹하여 회전합니다. 코일 표면도 같은 렌더의 검정 테이프 재질과 미세 링을 사용합니다. 회전·감김 면적은 tape-mechanism.js의 상태를 공유합니다. 원래 사진에 표현된 버튼의 위치에 투명한 HTML 클릭 영역을 연결하며, 새 사각 카드나 아이콘을 위에 덮지 않습니다.

현재 구성은 렌더 재질과 SVG 마스크를 조합한 2D 웹 인터페이스입니다. 실제 WebGL 3D 모델이나 순수 벡터 플레이어는 아닙니다. 사진 기반 허브의 반사까지 물리 시뮬레이션하지는 않습니다. 테이프 색은 삽입된 카세트 영역에만 적용하고 흰 플레이어와 파란 버튼 기호는 유지합니다.

문구는 실제 SVG·HTML 텍스트이며, 재질 위에 인쇄된 위치로 배치합니다. 현재 사용하는 화면은 이 절의 구조를 기준으로 보완합니다. 이전 V24–V26 절은 과정 기록입니다.

현재 사용하지 않는 FrontCassette·PlayerShell·원근 변형·평면 허브와 이전 플레이어 재질은 docs/asset-history/v27-retired-layers로 옮겨 삭제 없이 보존했습니다. 활성 플레이어 에셋 3장과 같은 렌더의 릴을 재사용합니다. 현재 파일 경로의 기준은 src/assets/index.js와 public/assets/manifest.json입니다.
